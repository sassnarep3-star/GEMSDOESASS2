Submitting the file

The gate that decides whether a file may be uploaded is run here, in this project, on the saved bytes — 13 automated checks. No human inspector is needed and none is used. A page visit never approves a file; the receipt does.

The six steps

  1. Download the primary file. gemsass2-collar4hex-c4-b37636-sweep2-20261031T060500Z-zeros.tif (107,486 bytes, deflate-compressed float32). The -zeros.zip sibling contains the identical bytes if the portal prefers a zip.
  2. Verify the bytes before uploading: shasum -a 256 <file> must equal c200ceccef52b45b979d5a2ad5c184516f8181828493400704a408074b7cbeb6. If it differs, the download was truncated — do not submit.
  3. Open the DrivenData submission form for competition 306 and attach the file.
  4. Paste the submission name as the file name is already unique; nothing else is required in the name field.
  5. Paste the note (≤140 characters): hex covering lattice, 4 px off-catalogue collar, same 37,654-dot budget as the 0.2778 champion (96 characters; it names the mechanism, the collar and the budget, and states the AI-use fact required by Rules §3.2 in the narrative, not here).
  6. Submit. Three submissions per week are allowed (Official Rules §3.2 / §3.4); exactly one is selected as final. Spending a slot on this file is the owner's decision — this page authorises the format and the uniqueness, not the slot.

Why the portal said “Predicted values must be in range [0, 1]”

The check is applied to every cell of the raster that the portal reads, not only to the study area. Three things trip it, and the generator now refuses to write any of them:

CauseWhat the bytes look likeHow this build avoids it
A NaN/inf nodata sentinel outside the footprint-3.4028235e+38 or nan in the cornersthe primary file writes 0.0 outside the footprint and sets nodata=None; the NaN twin exists only for GIS work and is labelled “not the portal file”
A negative fill value carried into a predicted cella dot with value -1.0 inside the study area (this actually happened in an earlier build, IR-VRC-01)the writer asserts min ≥ 0 and max ≤ 1 over the whole array before it saves, and check 10 re-reads the saved bytes
A float64 or integer rastervalues correct but dtype wrong, or scaled 0–255the writer forces float32 and checks the saved dtype (check 03)
