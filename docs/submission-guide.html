What the pipeline does automatically

Preflight commands

python scripts/prepare_data.py --data-dir data/raw
python scripts/fetch_focus_registry.py
python scripts/run_cdcc_experiment.py \
  --template data/raw/sample_submission.tif \
  --labels data/raw/labels.tif \
  --extensions path/to/official_extensions.tif \
  --radiometric path/to/official_radiometric.tif \
  --registry-dir data/registry_rasters \
  --input-provenance organizer_authenticated_local \
  --output-dir artifacts/cdcc

The run writes a run card, strict validator report, TIFF checksum, optional single-TIFF ZIP, and a ≤140-character note. It does not upload anything or spend a slot.

Fix for the observed range error

The submission writer rejects NaN/Inf or values outside [0,1] inside the template footprint. It then writes finite 0.0 outside the footprint too, so the whole array satisfies the conservative portal check.

It preserves the template’s CRS, shape, and affine transform.

If a future file is approved

Official portal sequence

  1. Choose only the exact `.tif` or matching one-file `.zip` named in a verdict: promote, ok_to_submit: true run card.
  2. Paste that run card’s bounded note into the portal’s optional note field.
  3. Use the official DrivenData competition page under the authorized account and within the weekly cap.
  4. Save the submission-page receipt alongside the uploaded file SHA-256. Only that receipt can support the label ORGANIZER-CONFIRMED.

This final portal interaction cannot be automated here because no competition authentication or weekly-slot authority is available. The lack of authentication is not a substitute for manual scientific inspection: all scientific gates run programmatically first.
