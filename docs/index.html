Why 0.2778 (GEMSDOE32 champion) won — and how this file was designed to beat it

  1. Metric algebra. Score = pooled distance-weighted Tversky, DTI = T/(T + 0.2·FP + 0.8·FN), 300 m triangular kernel. False positives cost 4× less than false negatives; a single binary dot costs ≤0.2 FP-weight yet earns kernel credit over a 3-px radius. Sparse binary dots strictly dominate continuous confidence maps under this pooled ratio.
  2. Catalogue masking. Known USGS/INGENIOUS fault pixels are masked at scoring (staff clarification #11516), so prediction mass on/near them is pure waste. The champion is literally the 0.2708 base with every dot within 2 px (200 m) of the catalogue deleted — FP down, T unchanged → 0.2708 → 0.2778.
  3. Corridor placement. Its 37,654 dots tile the catalogue flank corridors where undiscovered sub-parallel strands cluster.
  4. Headroom. The leaderboard top is 0.4413, so better *placement* (not more dots) wins: at DTI≈0.28 a dot must earn ≥0.056 kernel credit to pay for itself.
  5. This file. Keeps the three winning structural decisions (binary dots, B=2 prune, corridor confinement) but places dots by evidence — lidar scarp morphology (step/slope-excess/crest-convexity) × GeoDAWN U/Th fluid-pathway corroboration — instead of lattice resampling. On the leak-free SGMC off-catalogue instrument it recovers +40% more known-but-uncatalogued faults than the champion.
